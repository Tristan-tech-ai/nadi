# Menguji jalur absen BERHASIL ujung ke ujung (lanjutan Q-19)

Ditulis 1 Nov 2026. Celah: e2e absen.spec hanya menguji penolakan (kamera palsu Chromium `--use-fake-device-for-media-stream` menampilkan pola uji, bukan wajah, sehingga cek wajah MediaPipe di perangkat tidak pernah lolos). Jalur berhasil hanya dibuktikan di tes SQL (absen_qr). Bug di sambungan browser -> server action -> RPC tidak akan tertangkap.

## Pilihan
1. **Video wajah ke kamera palsu.** Chromium punya sakelar untuk mengganti kamera palsu dengan berkas video (`--use-file-for-fake-video-capture=<berkas .y4m>`; format lain seperti .mjpeg tidak disebut di komentar sakelar dan belum terverifikasi). Diverifikasi 1 Nov 2026 di sumber Chromium (https://chromium.googlesource.com/chromium/src/+/HEAD/media/base/media_switches.cc): `kUseFileForFakeVideoCapture = "use-file-for-fake-video-capture"` dengan komentar "Use an .y4m file to play as the webcam" (rincian di media/capture/video/file_video_capture_device.h); `use-fake-device-for-media-stream` yang dipakai absen.spec juga ada di berkas yang sama. Masalah besarnya: cek wajah Nadi meminta tantangan ACAK (kedip atau menoleh kiri/kanan). Satu video tetap hanya lolos satu tantangan, jadi tes menjadi rapuh atau harus memaksa tantangan. Butuh video wajah berlisensi bebas (CC0/domain publik, dicatat di docs/ASSETS.md) atau wajah buatan; ukuran y4m mentah besar (puluhan MB untuk beberapa detik), jadi tidak masuk repo.
2. **Urutan landmark terekam (disarankan untuk logika).** Rekam urutan hasil landmark wajah (angka, bukan gambar) untuk kedip dan menoleh, simpan sebagai fixture JSON kecil, lalu uji `nilaiWajah` / `yawDariLandmark` (src/lib/absen/wajah.ts) dengan urutan itu. Deterministik, tanpa video, tanpa data biometrik asli bila landmark dibuat dari model wajah sintetis.
3. **Sambungan browser -> server (disarankan untuk e2e).** Uji e2e jalur berhasil dengan komponen cek wajah diganti pada build uji lokal saja (variabel lingkungan yang hanya dibaca saat `NODE_ENV !== 'production'` dan tidak pernah ada di Vercel), sehingga yang diuji adalah: QR dipindai -> kode dikirim -> server action -> RPC absen_catat -> kejadian absen.masuk tercatat -> layar "Absen masuk tercatat". Produksi tetap memakai cek wajah sungguhan.

## Usulan tugas
Gabungan 2 + 3: fixture landmark (uji unit kedip/menoleh lolos dan gagal) dan e2e lokal jalur berhasil dengan penanda uji yang diblokir di produksi (tes yang membuktikan penanda tidak berlaku saat NODE_ENV=production). Kriteria: e2e lokal mencatat absen.masuk dan layar menampilkan konfirmasi; uji unit landmark merah sengaja sekali.
